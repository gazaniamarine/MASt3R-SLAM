# Route to visual subgoals

The adapter consumes the existing semantic BEV and a saved planner route. It
keeps every original path point and selects turn/intermediate subgoal indices.
It does not perform path planning, infer doorways, or execute robot actions.

Run from the repository root, replacing the map and planner paths with outputs
from the same run:

```bash
bash scripts/run_visual_subgoals.sh \
  --map logs/rover/my_run/map \
  --path /absolute/path/to/plans/map_dstt.npz \
  --path-key centerline \
  --plan-index 0 \
  --coordinate-order yx \
  --output logs/rover/my_run/visual_subgoals \
  --captioner smolvlm \
  --model HuggingFaceTB/SmolVLM-256M-Instruct \
  --device cuda:0
```

The vendored planner stores `centerline` and `traj` arrays as plans x points x 2,
in **y,x metres**. Use `--path-key traj` to follow a chosen refined trajectory.
Use `--coordinate-order xy` for your own N x 2 route in BEV x,y metres. JSON
arrays, JSON objects with the chosen key, and NPY arrays are also supported.
Input routes must already be validated for robot clearance. The adapter checks
vertex occupancy and bounds, but does not certify segment clearance.

For a model-free test use `--captioner none`. This still saves visual evidence
and geometric instructions. No model loads in this mode. SmolVLM loads once,
uses at most 32 new tokens per selected crop, and reuses captions within a run.
It needs compatible Transformers, Torch and Pillow in SAM2; see the
[official SmolVLM model card](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct).
Actual caption latency has not yet been measured on the rover GPU.

## Evidence alignment

The adapter reads the map's `_semantic_bev.npz` floor basis and sibling `.txt`
camera trajectory generated by `build_depth_semantic_bev.py`. Observation
timestamps plus the map's saved clock offset must match trajectory timestamps
(default tolerance 0.05 seconds). Camera positions and headings are projected
into the same BEV plane as the planner route.

It selects mapped landmarks within 3 m of each waypoint and reference camera
poses within 1.5 m / 45 degrees of the route approach. These are tunable
heuristics, not a guarantee of current visibility. Missing poses or timestamps
produce geometry-only subgoals. Captions use isolated object crops to limit
nearby objects contributing an incorrect label. They are marked unverified;
the geometry always supplies the action. Distinctiveness scoring, occlusion
prediction, dynamic-object rejection and landmark matching during execution
are future work.

## Output and navigation handoff

Open `index.html` to inspect each instruction, original frame and masked crop.
`subgoals.json` contains the complete route, waypoint indices, action, approach
heading, frame/entity references, captions and completion tolerances. Images
and masks are relative to that JSON directory.

A controller should track the original route between `path_start_index` and
`path_end_index`, then check position/heading before advancing. It must not
drive directly along waypoint chords or turn merely because a landmark is
recognized. Feed the current subgoal's instruction and evidence to a VLN model
through that model's supported interface. This adapter is the data handoff;
it does not implement a pretrained VLN policy or motor controller.
